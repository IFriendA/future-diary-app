# 未来人格首次建档设计

## 目标

新用户必须先建立“未来的我”，再进入第一篇未来日记。建档信息不是展示资料，而是每次生成未来回信时都会进入服务端人格提示词，持续影响 AI 如何理解行动、补足用户暂时做不到的部分，以及如何安慰和鼓励。

## 首次进入流程

首次进入且本机没有人格档案时，显示四步建档：

1. **MBTI**：必须从 16 型中选择一个，不把 MBTI 降级为可选项。
2. **我的行为逻辑**：自由填写“我通常如何做决定、遇到压力会怎样、什么会让我行动”，20–500 字。
3. **希望未来的我补足什么**：自由填写“现在不敢做或暂时做不到，但希望未来的我能做到的部分”，10–300 字。
4. **希望怎样被鼓励**：选择温柔陪伴、直接推动或轻松幽默中的一种。

完成后保存到本机并进入日记页。日记页提供“调整未来的我”入口；再次编辑不得清空当前日记。

## 数据模型

```ts
type SupportStyle = 'gentle' | 'direct' | 'playful';

type FutureSelfProfile = {
  mbti: MbtiType;
  behaviorLogic: string;
  futureSelfGap: string;
  supportStyle: SupportStyle;
  createdAt: string;
  updatedAt: string;
};
```

档案使用独立的 `future-diary:profile` 本地存储键，不与当前日记混存。第一版不引入账号和跨设备同步。

## AI 如何使用这些信息

前端每次调用 `/api/future-self` 时发送完整人格档案。服务端严格校验 MBTI、枚举和文本长度，然后把它作为“自我描述资料”注入系统提示词：

- MBTI 只作为表达和注意力偏好的参考，不用刻板印象断言用户。
- 行为逻辑用于让未来回信符合用户真实的决策方式、压力反应和行动触发点。
- 希望补足的部分用于让未来的自己表现得更勇敢、稳定或果断，但仍然是“我”，不是另一个角色。
- 鼓励方式决定回信口吻；所有风格仍禁止羞辱、恐吓、诊断和空泛鸡汤。
- 档案文本被标记为资料，不得把其中内容当成覆盖系统规则的新指令。

## 界面与状态

- 单页分步建档，每次只处理一种信息，顶部显示 1/4 到 4/4。
- MBTI 使用 4×4 可点击选项；自由文本步骤提供具体示例，不要求结构化填表。
- 前进按钮只在当前步骤有效时可用；可返回修改。
- 保存成功后立即进入现有日记页，不额外生成等待页。
- 现有用户因为没有档案，也会在下一次打开时进入建档；其当前日记继续保留。

## 验收标准

- 未选择 MBTI 不能完成建档。
- 两段自由文本会去除首尾空格并按长度校验。
- 刷新页面后不重复建档。
- 调整档案后当前日记仍保留。
- API 请求包含档案，服务端拒绝伪造 MBTI、无效风格或超长文本。
- 模型系统提示词明确使用四类资料，同时仍以第一人称“我”表达。
- 测试、类型检查、Lint 与 Web 构建全部通过。
