# 未来日记真实 AI 核心闭环设计

## 目标

交付一个可在手机网页直接体验的最小闭环：用户自由书写明天的日记，服务端调用 Pinova New API，让“明天的我”以第一人称返回未来记忆与结构化事项；用户可以把事项标记为部分完成、已经发生或明天继续，并在本机保留当前日记。

## 本轮不做

- 好友、组队、AI 与 AI 对话。
- MBTI 问卷和长期人格建模。
- 定时通知、推送和后台任务。
- 成就系统、装饰商城和复杂动效。
- 账号体系与跨设备同步。

## 用户流程

1. 首页显示“写给明天”和一个自由文本输入区。
2. 用户以已经发生的口吻书写，无需填写事项、时间、情绪等表单。
3. 点击“让明天的我先经历一次”后，前端调用 `POST /api/future-self`。
4. AI 返回一段第一人称未来记忆，以及从原文解析出的 1–5 个事项。
5. 用户可以分别标记“做到一点”“已经发生”“明天继续”。
6. 页面立即给予轻量正反馈；当前日记与状态保存在本机。
7. 用户可以清空当前记录并重新写一篇。

## 架构

### 前端

- Expo Router 继续承载 Web、iOS 和 Android 共用页面。
- `src/features/future-diary/` 按领域拆分类型、状态转换、存储和界面。
- 页面只访问同域 `/api/future-self`，不读取任何模型密钥。
- Web 使用 `localStorage` 保存一个当前日记；非 Web 平台本轮使用内存适配器，接入原生持久化留到 App 打包阶段。

### Vercel 服务端

- 根目录 `api/future-self.ts` 是唯一模型调用入口。
- 从服务端环境变量读取：
  - `NEW_API_BASE_URL=https://pinova.ai/v1`
  - `NEW_API_KEY=<Pinova Token>`
  - 可选 `NEW_API_MODEL=<固定模型 ID>`
- 使用 OpenAI 兼容的 `POST /chat/completions`，不引入模型厂商 SDK。
- 仅接受 `POST`，输入正文长度为 10–5000 个字符，请求超时 25 秒。

## 自动选择模型

若设置 `NEW_API_MODEL`，直接使用该模型。否则服务端调用 `GET /models`，排除 embedding、rerank、image、audio、video、moderation 等非文本对话模型，再按以下顺序匹配：

1. 名称含 `mini`、`flash`、`haiku` 或 `chat` 的文本模型。
2. 名称含 `gpt`、`claude`、`gemini`、`deepseek`、`qwen`、`glm` 的模型。
3. 剩余模型中的第一个。

选择结果在单个服务端实例中缓存 10 分钟。响应可以返回 `model` 供开发排查，但页面不把它作为产品内容突出展示。

## AI 输入与输出

### 请求

```json
{
  "diaryText": "明天下午我已经完成了提案……",
  "targetDate": "2026-08-27"
}
```

### 响应

```json
{
  "futureMessage": "我已经来到这一天了……",
  "moments": [
    {
      "id": "moment-1",
      "title": "完成提案",
      "timeWindow": "下午",
      "emotion": "踏实"
    }
  ],
  "model": "selected-model-id"
}
```

服务端验证并规范化模型输出：`futureMessage` 必须非空，`moments` 限制为 1–5 项；缺少 ID 时由服务端生成。模型返回非 JSON 时，服务端从文本中提取 JSON；仍失败则返回可理解的 `502`，不伪造 AI 内容。

## 未来人格提示词硬规则

- 你就是用户本人，处在明天的时间坐标上。
- 永远以“我”表达经历、想法和感受。
- 不得以“他/她/用户”等第三人称观察或评价用户。
- 不扮演老师、心理医生、监督者或宠物。
- 可以替今天暂时不敢做的自己先勇敢一次，但不夸大结果、不承诺现实必然发生。
- 未完成并不等于失败；回应要允许缩小、调整和继续。
- 不输出诊断、羞辱、恐吓、连续打卡压力或空泛鸡汤。

## 状态模型

每个事项状态为：

- `pending`：尚未反馈。
- `partial`：做到一点。
- `fulfilled`：已经发生。
- `carried`：明天继续。

状态转换只改变事项，不改写用户原文和 AI 的原始未来记忆。已完成事项再次选择其他状态时允许更正。

## 错误与安全边界

- 密钥只存在于 Vercel Secret，变量名不得以 `EXPO_PUBLIC_` 开头。
- 不记录日记正文、Authorization 头或模型原始响应到服务端日志。
- 只允许同源浏览器请求；服务端同时验证请求体和大小。
- 单个服务端实例按来源 IP 限制为 10 分钟最多 8 次生成；这是 MVP 防误用措施，不等价于正式账号鉴权。
- 上游 `401/403` 映射为“AI 服务配置无效”；`429` 映射为“AI 服务暂时繁忙”；超时映射为“未来的我暂时没有回信”。
- 上线给公众前必须补充账号鉴权和持久化限流，避免公开接口消耗账户额度。

## 测试

- 单元测试覆盖输入校验、模型筛选、JSON 提取、输出规范化和事项状态转换。
- API 测试使用注入式 `fetch`，不得访问真实 Pinova，也不得读取真实 Token。
- Web 构建验证静态页面与 Vercel Function 能同时存在。
- 线上验收使用一条无敏感信息的测试日记，确认真实模型返回第一人称内容，随后检查日志没有正文与密钥。

## 验收标准

- 空白或少于 10 字不能提交。
- 有效日记能够得到真实 AI 回应和 1–5 个事项。
- 回应以第一人称“我”为主体，不把用户称为“他”。
- 三种事项反馈均能即时更新并在刷新后保留。
- AI 失败时保留用户原文，允许重试，不显示伪造内容。
- `npm test`、`npm run typecheck`、`npm run lint`、`npm run build:web` 全部通过。
- Vercel Production 部署完成，`/api/future-self` 使用环境变量调用 Pinova。
